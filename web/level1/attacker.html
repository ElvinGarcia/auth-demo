Reading the stored value

pbkdf2_sha256 $ iterations $ salt $ hash

  • Salt: random per user, so two people with the same password get different hashes and one precomputed table cannot cover everyone.
  • Iterations: make every check deliberately slow. That cost is what protects a stolen table.
  • One-way: the server never needs the password back, only a way to check a guess.

What hashing fixed, and what it did not

  • Fixed: a breach no longer hands over readable passwords, and the replay above fails because the stored value is not a password.
  • Not fixed: weak passwords such as qwerty are only as strong as the person's choice, and anyone can still guess online without limit. Run the guessing script with --level 1 and compare its speed with Level 0.
  • Not fixed: phishing. A password typed into a fake page works for the attacker just as well, however it is stored.

That gap is why the next level adds a second factor.
