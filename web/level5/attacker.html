Level 5: Attacker view

The attacks that worked on every earlier level, tried one more time.

Simulation against this demo only, using the seeded demo accounts. Nothing real is involved.

1. Password known, no key

You have admin's password (admin123). There is no code to intercept, no mailbox to open and no secret to leak. All you can do is answer the challenge, and only admin's key can sign it.

4. A look-alike site

A phishing page cannot get a usable response either. Your browser, not the server, refuses first: it only offers a key made for the exact site name, and it writes the real origin into everything it signs, so a response made on a look-alike site is rejected here.

See it yourself: register a key at http://localhost:8000/level5/, then open the same page as http://127.0.0.1:8000/level5/. The browser will not use the key, or even allow registration, because that address is not the site name the key belongs to.

What this shows

  • A leak yields nothing. The server holds only public keys, so there is no shared secret to steal.
  • Nothing can be replayed. Each login signs a fresh random challenge that works once.
  • Phishing fails by design. The signature covers the site's real name, so a fake site cannot relay it. Earlier levels relied on the user spotting the fake.
  • A cloned key is noticed. The key keeps a counter; one that goes backwards is rejected. (Synced passkeys often keep it at zero, so this protects hardware keys best.)

What is still left at the top

  • Stolen sessions. After login, the session cookie is the credential. A malicious extension, malware, or a proxy that relays the whole site can take it.
  • Enrollment. Until a first key is registered, whoever knows the password can register their own. Seeded accounts here avoid it; real sites need a safe enrollment path.
  • Recovery and fallback. If the site also accepts SMS, email codes or a recovery question when a key is lost, an attacker simply picks the weakest option. The strongest factor protects nothing if a weaker one is also accepted.
  • The device itself. A passkey is only as safe as the phone or laptop and its account that holds it.
