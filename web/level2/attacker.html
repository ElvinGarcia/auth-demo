Level 2: Attacker view

You know the victim's password. Can a text message still stop you?

Simulation against this demo only. The SIM swap below moves a seeded demo account's fake number to this browser. Nothing real is involved.

Scenario

You already have admin's password (admin123): it was in the Level 0 dump and falls to guessing at Level 1. Level 2 adds a code texted to admin's phone. You do not have admin's phone, but you do not need it.

  1. SIM swap. Convince the carrier to move admin's number to a SIM you control. Carriers have been talked into this by phone, by insiders and by forged ID.
  2. Log in with the known password. The site texts a code to admin's number, which is now yours.
  3. Read the code on your phone (below) and enter it.

What this shows

  • The second factor was real. Without the swap, step 2 sends the code to a phone you cannot read, and the attack stops. Level 1's password alone would have been enough.
  • But the factor is a phone number, not a device. Whoever controls the number receives the code, and the site cannot tell the difference.
  • Phishing needs no swap. A fake login page can ask a victim for the code they just received and pass it to the real site within its 5-minute life. The text does not say which site is asking, and nothing in SMS binds the code to the real one. This demo does not build such a page.
  • What the code does well: it is single use, expires, and is capped at 5 guesses. Try entering wrong codes in step 3 until it locks.

The next levels move the second factor off the phone number: email, then an authenticator app, then a hardware-backed key.
